## 2. 项目概述与建设范围

### 2.1 业务定位

根据原表归纳，本系统是办公侧的信息公开业务工作入口，围绕政府信息公开、政府公报、政务信息编报、走好网上群众路线工作四个业务领域，提供事项办理、资料管理、采编制作及发布协同能力。入口通过京东侧进入办公系统，并实现单点登录（第3—7行）。

### 2.2 范围分层

| 层次 | 内容 | 说明 |
| --- | --- | --- |
| 统一入口 | 首页、我的工作台 | 总览、导航、快捷操作、待办及已办已发 |
| 核心业务一 | 政府信息公开 | 公开属性认定、主动或删减后公开、依申请公开、答复、延期 |
| 核心业务二 | 政府公报 | 文件筛选、标签、公报制作、排版校验、多渠道发布 |
| 核心业务三 | 政务信息编报 | 约稿通知关联、信息报送、采编审稿、刊物管理、发布及回收 |
| 核心业务四 | 走好网上群众路线工作 | 当前清单仅覆盖群众需求采集、导入和维护 |
| 业务支撑 | 权限、流程关联、文书模板、时限提醒、文件预览、接口和智能辅助 | 从各业务归纳出的公共需求，是否形成独立管理菜单另行确认 |

### 2.3 边界约束

- 门户网站上的公众申请入口由省政府网站承载，办公侧接收并办理；办公侧能否补录当面、邮寄申请存在冲突，详见第12章。
- 主动公开数据、公报候选文件与发文、签报等“一件事”有关，需明确本系统接收哪些流程结果及文件版本。
- 上报国务院办公厅的审核流程，原表明确不在当前系统创建（第42行）。
- 群众需求模块尚无交办、办理、督办、回复或满意度评价要求，不应直接扩展成群众诉求办理系统（第48—50行）。
- 系统外省直部门的数据接入、尚未落实的外部接口及智能化设想，应单独确认实施范围。

## 4. 业务全景与流程关系

### 4.1 政府信息公开

公开属性认定：部门起草 → 承办处室审核及保密审查 → 信息公开办复审 → 文秘处复核 → 按认定结果印刷或输出公开版。

主动／删减后公开：发文或签报流程完成 → 向省政府门户网站推送时同步到本模块 → 查询公开记录。

依申请公开：申请接收／登记 → 内容审核及必要补正 → 拟办 → 征求意见／协同会商 → 拟定答复 → 答复审签或延期申请 → 对外答复 → 全过程资料归档。

其中公开答复、延期申请是与依申请公开主业务关联的流程，不应仅作为无关联的表单设计。原表描述答复审批发起后当前环节完成、进入答复环节；延期申请发起后当前流程仍处于待办状态。具体状态和回流规则待确认（第17行）。

### 4.2 政府公报

文件汇入／部门填报 → 标注标签、筛选及备选 → 创建一期公报、选取多个文件 → 方正排版 → 文件返回及预览 → 人工校验 → 文件版、网络版或纸质版发布记录。

“备选库”和“备注标签库”的关系、校验与发布的前置约束尚未明确。

### 4.3 政务信息编报

报送通知／约稿任务 → 下级单位关联通知报送 → 共享库／备选库选稿 → 创建刊物与采编 → 按类别线上审核或线下送审 → 审核通过进入刊物库 → 发布 → 取消发布／删除进入回收站并可恢复。

信息报送是否需要上级审核、刊物审批由哪个系统承载、回收站恢复后的状态均待确认。

### 4.4 走好网上群众路线工作

手工录入／批量导入／条件具备后接口采集 → 采集记录查询 → 查看详情及维护。当前材料仅支持以上流程。

## 7. 业务规则、时限与状态需求

### 7.1 应优先明确的规则

- 公开属性取值及相互关系：原表起草建议将“不予公开（含删减公开）”列在一起，后续又将“主动公开或删减后公开”归类展示，需统一字段值及结果分类。
- 主申请与答复、延期流程之间的完成、等待、回流及关联关系。
- 补正、答复、延期的时限起算、工作日计算、补正是否暂停计时、节假日、临期阈值及超期处理。
- 原表记录“补正7个工作日内”“延期时限不超过20个工作日”（第17行），仅作为待业务确认的调研口径；原表未给出首次答复期限，本文不补充为既定规则。
- 公报文件筛选、标签、备选与一期多文件制作的关系，校验通过后如何发布及多渠道结果如何判断。
- 刊物类别与审核路径的对应，线下审核完成后如何记录和入库。
- 数据可修改、撤销、删除、恢复的阶段，以及已发布、已审签数据是否允许直接修改。

### 7.2 状态定义方式（建议）

应分别定义申请办理状态、审批状态、公开属性、发布状态和接口处理状态，避免用一个字段混合表达。各状态须给出进入条件、可执行操作、操作角色和下一状态；具体枚举在流程确认后确定。
